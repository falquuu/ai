## 📋 Описание проекта

Консольная программа на Python для поиска **всех совершенных чисел в диапазоне, заданном пользователем** (совершенное число равно сумме всех своих положительных делителей, исключая само число: 6 = 1 + 2 + 3), с вводом и выводом данных через консоль или файл. В состав проекта входят подсистема **резервного копирования и восстановления истории сканирования числовых осей**, пользовательская документация и тест-кейсы.

## 🎯 Задание

1. Создать консольную программу на Python для нахождения всех совершенных чисел в диапазоне, заданном пользователем (ввод/вывод через файл и через консоль).
2. Разработать алгоритм резервного копирования и восстановления истории математического сканирования числовых осей.
3. Разработать пользовательскую документацию (ТЗ, README на русском и английском языках, регламент технического обслуживания) и зафиксировать её вместе с проектом в GitHub.
4. Составить тест-кейсы и проверить работоспособность ключевых модулей на соответствие ТЗ.

## 🎮 Использование программы

### Поиск совершенных чисел

```bash
# Ввод из консоли: программа запросит начало и конец диапазона
python -m perfect_numbers find

# Границы аргументами
python -m perfect_numbers find -s 1 -e 10000

# Ввод из файла (TXT, CSV или JSON определяются по расширению)
python -m perfect_numbers find -i examples/range.csv

# Результат в файл (.json — JSON, иначе — текст)
python -m perfect_numbers find -i examples/range_small.txt -o result.json

# Сохранить сканирование в историю data/history.json
python -m perfect_numbers find -s 1 -e 10000 --save
```

Диапазон включает обе границы. Допустимо: `1 ≤ начало ≤ конец ≤ 10¹²`, длина диапазона — не более 5 000 000 чисел. Источники данных (`-i` и `-s/-e`) одновременно не указываются.

### Форматы входного файла

```
# TXT / CSV — два числа: начало и конец (разделитель: пробел, запятая, «;» или табуляция)
start,end
1,10000
```

```json
{"start": 1, "end": 10000}
```

JSON также может быть списком `[1, 10000]`. Пустые строки, строки с `#` и заголовок `start,end` игнорируются.

### История и резервное копирование

```bash
python -m perfect_numbers history        # показать историю сканирований
python -m perfect_numbers backup         # создать копию истории в backups/
python -m perfect_numbers list-backups   # список копий с проверкой целостности
python -m perfect_numbers verify         # проверить все копии
python -m perfect_numbers restore        # восстановить из самой свежей копии
python -m perfect_numbers restore --file backups/history_20261021_022708_491394.json
```

Общие параметры: `--data-file` (по умолчанию `data/history.json`), `--backup-dir` (`backups`), `--keep` (число хранимых копий, по умолчанию 10).

### Использование как Python-модуля

```python
from perfect_numbers.core import analyze, find_perfect_numbers, is_perfect, RangeError
from perfect_numbers.io_handlers import read_range_file
from perfect_numbers.backup import HistoryManager

# Расчёт
print(analyze(1, 10000))
# {'start': 1, 'end': 10000, 'count': 4, 'numbers': [6, 28, 496, 8128]}

print(is_perfect(28))            # True

# Чтение диапазона из файла
start, end = read_range_file("examples/range.csv")   # (1, 10000)

# Некорректный диапазон
try:
    analyze(10, 1)
except RangeError as err:
    print(err)                   # Конец диапазона не может быть меньше начала.

# История и резервное копирование
manager = HistoryManager("data/history.json", "backups", keep=5)
manager.add_record(analyze(1, 100), elapsed=0.01)
backup = manager.create_backup()
manager.restore(backup)
```

## 📊 Основные функции

### Модуль `core`

- `analyze(start, end)` — результат сканирования: границы, количество и сами числа
- `find_perfect_numbers(start, end)` — список совершенных чисел диапазона
- `is_perfect(n)` / `divisor_sum(n)` — проверка одного числа / сумма его собственных делителей
- `divisor_sums(start, end)` — суммы делителей для всего диапазона (сегментное решето)
- `validate_range(start, end)` — проверка: целые числа, `1 ≤ начало ≤ конец ≤ 10¹²`, длина ≤ 5 000 000

### Модуль `io_handlers`

- `read_range_file(path)` — чтение диапазона из TXT / CSV / JSON
- `read_range_console()` — интерактивный ввод из консоли
- `parse_range_text(text)` / `parse_range_json(text)` — разбор текста и JSON
- `format_result(result)` / `write_result_file(path, result)` — вывод в текст / запись в TXT / JSON

### Класс `HistoryManager`

- `add_record(result, elapsed)` / `load_history()` — работа с историей
- `create_backup()` — создание копии с манифестом (SHA-256) и ротацией
- `list_backups()` / `verify_all()` — список и проверка копий
- `verify_backup(path)` — проверка целостности одной копии
- `restore(path=None)` — восстановление (по умолчанию из самой свежей копии)

## 🔍 Алгоритм поиска

Сегментное решето сумм делителей: для диапазона `[a; b]` создаётся массив длиной `b − a + 1` из единиц; для каждого `d` от 2 до `⌊√b⌋` и каждого кратного `m = d·q ≥ d²` к `m` прибавляются `d` и `q` (если `q = d` — один раз). Число совершенно, если накопленная сумма равна самому числу. Сложность — O(L·ln √b) по времени и O(L) по памяти, где L — длина диапазона. Диапазон `1…1 000 000` обрабатывается примерно за 1 секунду.

## 🔄 Алгоритм резервного копирования

1. Хранилище истории проверяется и копируется в `backups/history_<дата>_<время>.json`; повреждённые данные не копируются.
2. Рядом записывается манифест `*.manifest`: SHA-256, число записей, размер, дата создания.
3. Записи атомарные (временный файл → замена), сбой не оставляет наполовину записанных файлов.
4. Ротация: хранятся только последние N копий (`--keep`).
5. Восстановление: проверка копии → сохранение текущего состояния отдельной копией → атомарная замена. Повреждённая копия отклоняется, хранилище остаётся нетронутым.

## 🧪 Тестирование

Проект включает **68 автоматических тестов** и **42 тест-кейса**:

**Unit-тесты:**

- Расчёт: известные числа (6, 28, 496, 8128, 33 550 336), границы, диапазоны без результата, сверка решета с прямым перебором
- Некорректные диапазоны: начало < 1, конец < начала, слишком длинный диапазон, нецелые значения
- Разбор TXT / CSV / JSON, разделители, BOM, ошибки ввода с номером строки
- Резервное копирование: манифест, ротация, повреждённая копия, восстановление, атомарность

**Интеграционные тесты:**

- Полные сценарии командной строки, коды возврата
- Цикл «сохранить → копия → изменить → восстановить»

Таблица тест-кейсов и результаты проверки — в [docs/test-cases.md](docs/test-cases.md).


## ⚠️ Коды возврата

| Код | Значение |
|---|---|
| 0 | Успешно |
| 1 | Ошибка данных (некорректный ввод, файл не найден, недопустимый диапазон) |
| 2 | Неверные аргументы командной строки |
| 3 | Ошибка хранилища или резервной копии |
