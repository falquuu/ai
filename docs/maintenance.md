# Регламент технического обслуживания

Документ определяет порядок обслуживания `perfect-numbers-tool` и защиты накопленной истории сканирований.
Связанные документы: [ТЗ](TZ.md), [Тест-кейсы](test-cases.md), [Правила Git](GIT.md).

## 1. Общие положения

- **Объект обслуживания:** программное средство, файл истории `data/history.json`, резервные копии `backups/`.
- **Ответственный:** администратор / владелец репозитория *[ФИО]*.
- **Периодичность** привязана к интенсивности использования; ниже указаны минимальные рекомендации.

## 2. Плановые работы

| Периодичность | Работа | Команда / действие | Критерий успеха |
|---|---|---|---|
| Перед важными изменениями истории | Резервная копия | `python -m perfect_numbers backup` | «Копия создана», код 0 |
| Ежедневно (при активной работе) | Резервная копия | `python -m perfect_numbers backup` | то же |
| Еженедельно | Проверка целостности всех копий | `python -m perfect_numbers verify` | «повреждено: 0», код 0 |
| Еженедельно | Просмотр списка копий и объёма каталога `backups/` | `python -m perfect_numbers list-backups` | Копии «OK», число ≤ `--keep` |
| Ежемесячно | Контрольное восстановление в тестовый каталог | см. п. 4.3 | История совпадает с ожидаемой |
| Ежемесячно | Запуск автотестов | `python -m unittest discover -s tests` | «OK», все тесты пройдены |
| Ежеквартально | Обновление Python до поддерживаемой версии, повторный прогон тестов | `python --version` + тесты | Тесты пройдены |
| Ежеквартально | Копирование каталога `backups/` на внешний носитель | вручную | Копия каталога на втором носителе |
| При каждом релизе | Обновление документации, тега версии | см. `GIT.md` | Тег `vX.Y.Z`, актуальные README/ТЗ |

> Правило 3-2-1: **3** копии данных, на **2** разных носителях, **1** — вне основного рабочего места.

## 3. Параметры хранения

| Параметр | По умолчанию | Рекомендация |
|---|---|---|
| `--data-file` | `data/history.json` | Каталог на надёжном диске |
| `--backup-dir` | `backups` | Отдельный диск/каталог, не совпадающий с каталогом истории |
| `--keep` | 10 | 10–30; каждая копия ≈ размеру истории |

Файлы `data/` и `backups/` исключены из Git (`.gitignore`) — это пользовательские данные, а не исходный код.

## 4. Порядок действий

### 4.1 Создание и проверка копии

```bash
python -m perfect_numbers backup
python -m perfect_numbers verify
```

### 4.2 Восстановление после сбоя

1. Остановить работу с программой; ничего не удалять вручную.
2. Посмотреть копии: `python -m perfect_numbers list-backups`.
3. Выбрать последнюю копию со статусом **OK**.
4. Восстановить:
   - из самой свежей: `python -m perfect_numbers restore`;
   - из выбранной: `python -m perfect_numbers restore --file backups/history_<…>.json`.
5. Убедиться: `python -m perfect_numbers history`.
6. Зафиксировать инцидент (п. 7).

Если `restore` сообщает о повреждённой копии — хранилище **не изменено**; выберите предыдущую копию. Перед заменой программа сохраняет текущее состояние отдельной копией (или как `history.json.corrupt-<время>`, если файл уже повреждён) — откатиться можно тем же способом.

### 4.3 Контрольное восстановление (учения)

```bash
python -m perfect_numbers restore \
    --data-file /tmp/drill/history.json --backup-dir backups \
    --file backups/history_<…>.json
python -m perfect_numbers history --data-file /tmp/drill/history.json
```

Рабочая история при этом не затрагивается.

## 5. Диагностика

| Симптом | Вероятная причина | Действие |
|---|---|---|
| «Ошибка хранилища: Файл истории повреждён» | Обрыв записи вне ПС, ручная правка | `restore` из последней OK-копии |
| «Контрольная сумма не совпадает» | Копия изменена или повреждена | Использовать другую копию; проверить носитель |
| «Манифест копии не найден» | Удалён `.manifest` | Копия непригодна; использовать другую |
| «Хранилище истории не найдено» при `backup` | История ещё не создана / неверный `--data-file` | Проверить путь или выполнить `find … --save` |
| «Резервные копии не найдены» | Неверный `--backup-dir` или копий нет | Проверить каталог |
| `ModuleNotFoundError: perfect_numbers` | Запуск вне корня проекта | `PYTHONPATH=src` или `pip install -e .` |
| Нечитаемая кириллица в консоли Windows | Кодировка | `chcp 65001` |
| «Длина диапазона не должна превышать…» | Диапазон > 5 000 000 | Разбить на окна |

## 6. Обслуживание кода и репозитория

1. Изменения вносятся только через ветки и Pull Request ([GIT.md](GIT.md)).
2. Перед слиянием — зелёный прогон CI (Windows / Linux / macOS, Python 3.10–3.13).
3. Любое изменение формата истории: увеличить `HISTORY_VERSION`, описать миграцию, добавить тесты.
4. Любое изменение поведения → обновить ТЗ, README (ru и en), тест-кейсы.
5. Релиз: обновить версию в `pyproject.toml` и `__init__.py`, создать тег и GitHub Release.
